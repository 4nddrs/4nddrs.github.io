# Terminal redesign — 4nddrs

Objective: replace the six-panel board with a page that reads as a tiling window manager on a dark desktop — one terminal window per content section. Supersedes `portfolio-hardening.md` for visual decisions (its SEO and metadata fixes are kept).
Branch: none (not a git repository). Runner: none; verification is `tsc --noEmit`, `vite build`, and `odd/audit-contrast.mjs`.

## Specs

- **S1** The page is a tiling-window mosaic: seven terminal windows placed by a CSS grid. At ≥1440px wide and ≥700px tall the mosaic fills the viewport exactly and the page never scrolls; every window fits its content at those sizes. Below that it grows with its content and the page scrolls, because seven readable windows no longer fit and a silently clipped window is worse than a page that moves. The status bar stays pinned to the bottom edge either way. Column count degrades to 2 at ≤1100px and to 1 at ≤760px.
- **S2** Every window has a title bar with three monochrome dots and an `<h2>` carrying its command (`whoami`, `ls ~/projects`, `bat stack.toml`, `bat notes.md`, `bat interests.txt`, `./connect.sh`, `git log --experience`), so the document outline stays valid.
- **S3** Header reads `Andrés Menchaca` / `systems engineer · cbba, bolivia` from his live site, not the previously invented `Spain · CET`.
- **S4** Contact links are the real ones: GitHub, `linkedin.com/in/4nddrs` (confirmed by the user as the correct profile), `x.com/4nddrs` (given by the user), `4nddrs.dev@gmail.com`, and `CV_andresMenchaca.pdf`, the CV the user supplied, served from `public/` and offered as a download.
- **S5** The six real repositories are listed with their descriptions and open in a new tab.
- **S6** All text reaches 4.5:1 contrast on the lightest surface it is painted on (`#0a0d16`); nothing renders below 13px.
- **S7** The page ends in a status bar: the prompt `4nddrs@dev:~` + `$` with a blinking caret on the left, availability on the right.
- **S8** No backend and no data fetching: the page is static and content lives in `src/content.ts`. The only client state is which project detail is open, derived from the URL hash.
- **S9** Typography is Fira Code, matching his live site.
- **S10** Windows fill their grid slot and the mosaic covers the viewport at desktop widths. Leftover height is redistributed into the windows, never left as margin around a floating mosaic.
- **S11** Inside a window, output starts under the title bar and the rest of the window stays empty, like a terminal whose buffer is shorter than the screen. Row rhythm scales with viewport height so tall screens get readable spacing instead of one tight block at the top.
- **S12** A row never shrinks below its content: if the content does not fit the viewport, the page scrolls instead of clipping a window.
- **S13** Technologies, tools and services carry a 16px brand glyph: one per stack chip, one per project tag, one per contact row. Brand fills are lightened only when the original is too dark to read on `--surface`.
- **S14** Color follows a bat-style syntax palette instead of uniform grey: keys and contact labels purple (`#d2a8ff`), project names blue (`#79c0ff`), prose and values neutral, terminal prompt accents green. Contrast is unchanged.
- **S15** Hover and keyboard focus paint a faint neutral wash (`rgba(255,255,255,0.045)`). No accent tint and no caret bar.
- **S16** `whoami` carries the identity in this order: the handle `4nddrs` as the title with `Andrés Menchaca` under it at 13px in `--dimmer`; `systems engineer · backend · linux-first`; `where · south america` with the label dimmer than the value; `I build systems that solve real problems.`; `I care about clean architecture, scalable backends, and tools that stay out of the way.`; then the philosophy block labelled `~/philosophy` with `I want to solve hard problems for people I care about.`
- **S17** `ls ~/projects` lists every project with a one-line statement of the problem it solves, its technologies and its GitHub link. Descriptions come from the repository README and metadata; nothing is invented.
- **S18** A project opens a dedicated detail window: `#<slug>` in the URL, `cd <slug>` and `cat README.md` prompts, the sections the repository actually documents (overview, problem, approach, architecture, implementation, stack), a source link and a demo link only where one exists (`snag`). Esc, a close button and a backdrop click return to the mosaic; focus is trapped inside while open and restored on close; deep links render on first load.
- **S19** `bat stack.toml` renders the stack as a configuration file: an ordered list with a fixed line-number gutter, `[section]` tables in `--blue`, keys in `--key`, `= [ … ]` punctuation in `--dimmer` and quoted strings in `--fg`. Sections are core / backend / infrastructure / frontend / ai, and the technologies sit one level deeper as `lang`, `server`, `data`, `runtime`, `vcs`, `workflow`, `build`, `tools`, `ml`. No badges, no bars, no logos; backend and infrastructure carry the most lines, which is where the emphasis comes from.
- **S20** `git log --experience` renders the four roles the owner supplied: Ninescale (software developer · 2026– · robotics · ai tools · teams), 4nddrs (software architect & developer · freelance · feb 2026–), Paramo Games and EDUBO (software developer · internship · 2025). The date rides on the organization line rather than owning a column, because in a 262px window that column cost every detail line 59px. Nothing beyond what he provided is claimed.
- **S21** `bat notes.md` exists without fabricated entries: it states that no notes are published yet and where updates will appear.
- **S22** `./connect.sh` lists the five verified channels as a mark plus the channel itself, with no lead paragraph and no channel-name column: the icon identifies the channel and the value is the link. The CV row downloads `CV_andresMenchaca.pdf`. Each row carries a copy button as a sibling of the link — never nested inside the anchor — that copies the destination (the absolute URL, or the bare address for the mail link), confirms with a check for 1.4s, and announces the result through one visually hidden live region. If the async clipboard API refuses, a legacy selection copy runs before the row reports failure.
- **S23** The desktop mosaic reads `profile | projects projects | experience` / `stack | notes | contact | interests`; the projects window spans two columns so every description stays on one line. Mobile stacks in reading order: profile, projects, stack, experience, notes, contact, interests.
- **S24** The status bar carries only the prompt (`4nddrs@dev:~$` with the caret). No availability indicator is shown: a claim about being open to work is not something the page asserts.
- **S25** The avatar is served at 184px from the 1024px source; every asset is local and no new runtime dependency is added.
- **S26** A stack row wraps between values, never before a separator: each value carries its trailing `·` inside a `nowrap` span and the break opportunity sits between spans, so no continuation line starts with a stray dot.
- **S28** Every panel shares one surface (`--surface`), one 1px inset top highlight and the same `--rule` edge. Rank is carried by title colour and type alone: `whoami` and `ls ~/projects` keep a `--dim` title, the rest `--dimmer`.
- **S34** The project list is ordered snag, mkf, smart-gym, eppCheck, backend-Country, linux-config. Every row looks the same at rest; the only state is the neutral wash plus a `--ribbon` marker on the row the pointer or the keyboard is on.
- **S35** The status bar is a small command surface: a real input in the prompt line, a scrollback panel floating above it, and a fixed command set — `help`, `whoami`, `projects`/`ls`, `experience`, `stack`, `contact`, `interests`, `cd <project>`, `clear`. It never evaluates input, never touches the filesystem and never runs anything from the system; an unknown word gets a short reply and a pointer to `help`. Arrow keys walk the command history, Esc clears and blurs, and the whole portfolio stays usable without ever touching it.
- **S36** Experience entries open a window like projects do, sharing one `Dialog` component: organization, title, kind, full period, place, summary, contributions and skills — only the fields the source documents. A role with no detail says so and points at `content.ts` instead of being padded.
- **S29** `ls ~/projects` is the centrepiece: project names are 15px in `--blue` against 14px `--dim` descriptions, a hovered or focused row takes a `rgba(255,255,255,0.055)` wash plus a 2px neutral `--ribbon` marker on its left edge, and the title bar's right slot shows `~/projects/<slug>` while a row is hovered or focused and `6 projects` at rest.
- **S30** `bat stack.txt` emphasises `core`, `backend` and `infrastructure` by putting their values in `--fg` and their labels at weight 500; `frontend`, `workflow` and `ml` stay in `--dim`. No icons, no badges.
- **S31** `bat interests.txt` shows each topic with a one-clause gloss that describes the field, not a personal claim: `cybersecurity — how systems fail`, `linux & terminal automation — reproducible shell setups`, `smart contract security — code that moves value`, `clean architecture — boundaries over patterns`, `web3 infrastructure — nodes and protocols`.
- **S32** An empty section renders a git-graph rail: a hollow node, a dashed vertical rule down the panel, one line naming the data it will hold, and the pointer to `content.ts` pinned as a footer. No entry, company, date or article is implied.
- **S33** The status bar adds the environment on the right (`linux · zsh · nvim`, taken from linux-config). DOM order follows the priority order — identity, projects, experience, stack, contact, notes, interests — so tab order matches the visual order at every breakpoint.
- **S27** Below 800px of viewport height the vertical rhythm tightens (line height 1.55, gaps 7px, body padding 10/16px, avatar 38px, title 18px) rather than letting a window overflow.
